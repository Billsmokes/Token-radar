# Accessibility — Token Radar

Token Radar ranks pre-token DeFi protocols by implied launch value. The
output is a static dashboard (`dashboard/`) that renders the whole board —
board view, per-protocol detail view, filtered views (search, category,
chain, watchlist-only), a live-token view, the model formula, and a category
breakdown — with no network. It is generated by a Node script from a sealed
snapshot.

## Goals

Accessibility matters because the people who read the radar include people
who navigate by keyboard, use screen readers, or rely on high-contrast and
reduced-motion settings. Our target is to meet **WCAG 2.2 Level AA** over
time.

That target is an aim, not a conformance claim. No formal accessibility
audit or evaluation has been carried out yet, so we do not claim conformance
with any WCAG version or level.

## What this covers

- The static dashboard: board, detail, and filtered views, and the model
  documentation rendered in the page.
- The underlying data files (`board.json`, `data.js`) are plain structured
  data and can be read without the dashboard.

## Reporting an accessibility barrier

If you hit a barrier while using Token Radar, please open a
[GitHub Issue](https://github.com/Billsmokes/Token-radar/issues/new) in this
repository and add the `accessibility` label. If the label is not available,
put the word "accessibility" in the issue title.

You do **not** need to disclose a disability, and screenshots or recordings
are optional. The following details help us reproduce the problem:

- The task or view affected (for example, "board view" or "protocol detail")
- What you expected to happen and what happened instead
- Browser and operating system
- Assistive technology used, if any (for example, a screen reader or
  keyboard-only navigation)

## What happens after you report

1. The maintainer acknowledges the issue and triages it.
2. The issue is tracked with the `accessibility` label, and status updates
   are posted on the issue as work progresses.
3. If a fix is made, the reporter is invited to verify it.

We aim to acknowledge reports promptly, but this is a one-maintainer project,
so triage and fix times vary.

## Supported environments

- Modern browsers: Chrome, Firefox, Safari, Edge (latest versions)
- Desktop and mobile

## Known limitations

- The dashboard has **not yet been tested with screen readers or by
  keyboard-only users**. The board is a dense data table (213 rows); table
  output can be difficult to follow with a screen reader, and keyboard
  navigation across the filtered views has not been verified.
- The raw data (`board.json`, `data.js`) is available as an alternative way
  to read the rankings without the dashboard.
- This list will be updated as testing is done and issues are found.

## Contributor expectations

Contributors changing the dashboard should:

- Keep interactive elements reachable and operable by keyboard.
- Keep table structure semantic (headers, captions) so the board stays
  navigable by assistive technology.
- Not rely on colour alone to convey meaning.
- Check their changes with a keyboard and, where possible, a screen reader,
  and note the results in the pull request.
